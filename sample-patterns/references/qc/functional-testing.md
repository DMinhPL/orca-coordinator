# QC Functional Testing

Derive cases from acceptance criteria and behavior transitions.

Cover, when relevant:
- primary success;
- invalid/missing input;
- empty/no-data state;
- error/timeout/cancellation;
- duplicate/repeated action;
- permission/session boundary;
- state transition before/after refresh/reconnect.

Use the cheapest reliable verification method: focused automated test, targeted command, browser/API check, or static evidence when execution is unavailable.
